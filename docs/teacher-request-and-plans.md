# 老師的請求與方案 A / B

## 老師原文（2026-10-26，使用者轉貼）
> 想請問 可以設計一個A I，讓各組學生念讀 我上次食譜的步驟，並且給他們評分或回饋嗎？
>
> 不用評分也沒關係，有的話很好，但沒有也沒關係
>
> 最主要是要確認他們會念讀嗎？
>
> 就想說 透過這個城市活動，讓他們可以在小組間自己進行
>
> 我想讓他們剪貼排完順序之後，再透過程式把步驟一到最後一步驟唸讀一次

（「城市活動」應是「程式活動」的輸入錯誤。）

## 給使用者的完整分析（2026-10-26）
- 畫面構想：選組別 → 依正確順序一次顯示一步 → 唸到的字即時變綠、沒唸到的留灰 → 全部唸完顯示結果與要再練的字。照正確順序帶唸，也等於讓學生對照自己剪貼的順序。
- **方案 A（不評分，有簡易分數）**：用 Chrome / Edge 內建語音辨識，程式比對原文，算出唸到幾成、哪些字漏掉。成本 0。限制：只支援 Chrome / Edge 且要連網，iPad Safari 不穩；辨識器會「幫忙猜」，只能確認有沒有唸，看不出發音準不準；多組同時唸會互相干擾。開發約半天到一天。
- **方案 B（有分數）**：Azure 發音評估，每個字、甚至每個音節都有分數（準確度、流暢度、完整度、語調）。成本：每月 5 小時免費；超過後基本每小時約 US$1.3，加購的發音評估另計（保守估每小時 US$2–3）；每班約 US$0.3–1.5。需要 Azure 帳號，加上 Cloudflare 小程式保管金鑰。開發約 1–2 天。
- AI 評語（LLM）：每班不到台幣 1 元；用固定範本效果也差不多。
- 隱私：兩個方案都會把學生聲音送到雲端（A：Google；B：Microsoft），建議先告知學校或家長。claude.ai 預覽不能用麥克風，要在 Cloudflare 網站上用。
- 當時的建議：先做 A，需要分數再升級 B。

## 給老師看的精簡版（使用者要求「簡短、老師看得懂」）
**方案 A：確認有沒有唸（免費）**
- 學生對著電腦或平板唸，畫面會顯示唸到哪些字、漏了哪些字，最後告訴他們「唸對幾成」。
- 費用：0 元。
- 限制：
  - 要用 Chrome 或 Edge 瀏覽器，而且要有網路，iPad 可能不太穩。
  - 只能判斷「有沒有唸出來」，看不出發音準不準。
  - 各組要分開一點，不然聲音會互相干擾。

**方案 B：有分數（幾乎免費）**
- 除了方案 A 的功能，每個字還會打分數（綠、黃、紅），並給星星和一句簡單的英文回饋，例如「Great job! Try *whisk* again.」
- 能看出發音準不準、唸得順不順。
- 費用：每個月有免費額度，一般一個班用不完。就算超過，每次上課大約 10–50 元台幣。

**建議**：先用方案 A，確認學生會唸；之後想要分數，再升級成方案 B。

## 決定（2026-10-27）
使用者：「最後要決定做方案 B 了」。規格見 `plan-b-pronunciation.md`。方案 A 保留為 B 的退路（token 失敗或瀏覽器不支援時）。
